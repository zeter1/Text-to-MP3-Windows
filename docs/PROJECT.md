# Проект

## Назначение и точки входа

Windows-программа читает текст через Microsoft SAPI и создаёт MP3 через FFmpeg. Стабильная точка запуска — `text_to_mp3.py`; код реализации расположен в пакете `tts_app/`.

Для навигации по коду **сначала `AGENTS.md` → `docs/CODEMAP.md` → `python tools/where.py <symbol>`**. Не читать все модули подряд.

## Постоянные данные

- `Настройки программы/settings.json` — общие настройки.
- `Настройки программы/workspace.json` — состав и параметры вкладок.
- `Настройки программы/Вкладки/*.txt` — пользовательский текст вкладок.
- `Бэкапы текста MP3` — снимки текста для безопасного создания MP3.
- `Незавершённые задачи` — восстановление прерванных конвертаций.
- `Логи проблем/session_*` — диагностические сессии.

Пути вычисляются от корня программы, несмотря на размещение implementation modules внутри `tts_app/`.

## Context budget

Обычный implementation owner должен оставаться ≤24 КБ. Facade/composition root — ≤4 КБ. Исключение: `task_conversion_worker.py` ≤60 КБ, потому что это один транзакционный pipeline; для него используется `docs/WORKER_MAP.md` и `CODEX-REGION` markers.

## Проверки

Единый быстрый gate:

```bash
python tools/verify.py
```

Он выполняет compileall, smoke helpers, import/facade checks, preview/logger regression tests, size budgets и обновляет symbol/module indexes. Запускать в source mirror без runtime/user data: storage при импорте зависит от `__file__`; один cwd не даёт изоляции. Подробный контракт: [LOGGING_FOR_AI.md](LOGGING_FOR_AI.md).

Чтение подтверждается и удаляется после целого успешно проверенного SAPI блока. Незавершённый блок при ошибке/Stop сохраняется; настройки устройства не подменяются. Диагностика и oracle вывода описаны в том же [контракте логов](LOGGING_FOR_AI.md).

При захвате горячей клавишей действующий фильтр оставляет русские буквы, цифры, точки, запятые и пробелы. Если после фильтрации нет букв или цифр, фрагмент не добавляется и не запускает чтение: одни знаки препинания не дают звука. Текущее чтение, пауза и закладка сохраняются; следующий обычный фрагмент принимается как прежде. Обработчик — `AppHotkeysMixin._on_tab_copy_hotkey` в `tts_app/app_hotkeys.py`.

Эти проверки не доказывают реальную работу Windows SAPI, конкретного аудиоустройства, глобальных горячих клавиш или длительной MP3-конвертации. Для таких изменений нужен runtime-check на Windows.


## Уведомления о готовых файлах

Событие успешной конвертации `done` обрабатывается на главном Tk thread. Вместо модального «ОК» модуль `tts_app/conversion_notifications.py` создаёт отдельное окно для каждой завершённой задачи. Окна остаются поверх обычных окон внизу справа на мониторе главного окна, вне панели задач; следующие уведомления размещаются выше, затем в соседнем столбце. Уведомление закрывается своим крестиком, без таймера. Сворачивание главного окна и «Показать файл» его не закрывают. При выходе из программы дочерние окна уничтожаются вместе с Tk root; в ходе shutdown новые уведомления не создаются.

«Показать файл» открывает Проводник с выделением готового MP3. Если файл уже удалён, открывается его существующая папка; если недоступна и папка, показывается ошибка, уведомление сохраняется. Новые папки при этом не создаются. Формат задач и конвертационный pipeline не меняются.

`tools/test_conversion_notifications.py` входит в общий gate; опция `--gui` дополнительно проверяет реальные Tk-окна на Windows с синтетическими данными (несколько завершений, крестик, сохранение после открытия, сворачивание, shutdown, main-thread guard). Native mouse/focus, фактическое выделение в Проводнике и packaged EXE требуют отдельной проверки: запустить две короткие конвертации, свернуть главное окно, затем открыть файл из каждого уведомления и закрыть только одно крестиком.
