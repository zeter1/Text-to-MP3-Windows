# Сборка Text-to-MP3-Windows в готовый EXE

`build_exe.bat` собирает полностью готовую Windows-версию программы. После успешной сборки пользователю не требуется отдельно устанавливать Python, `pywin32` или FFmpeg.

## Как собрать

1. Скачайте репозиторий и распакуйте его в обычную папку Windows.
2. Дважды щёлкните `build_exe.bat`.
3. Дождитесь сообщения:

```text
[OK] READY BUILD CREATED AND VERIFIED.
```

4. Готовая программа находится здесь:

```text
dist\Text-to-MP3-Windows\Text-to-MP3-Windows.exe
```

Переносите **всю папку** `dist\Text-to-MP3-Windows`, а не один EXE: рядом с ним находится папка `runtime` с Python runtime, pywin32/COM-компонентами и встроенным FFmpeg.

## Что BAT делает автоматически

Скрипт:

- ищет Python 3.13;
- при его отсутствии пытается установить Python 3.13 для текущего пользователя через `winget`;
- создаёт отдельное `.build-venv`;
- устанавливает зависимости из `requirements.txt` (`pywin32`, `imageio-ffmpeg`);
- устанавливает PyInstaller 6.22.3 и hooks;
- выполняет `pip check`;
- компилирует большой основной модуль;
- проверяет Windows SAPI через COM;
- проверяет, что `imageio-ffmpeg` реально содержит рабочий `ffmpeg.exe`;
- запускает offline repository tests;
- очищает старые `build/`, `dist/` и `.spec`;
- создаёт стабильную ONEDIR-сборку;
- явно собирает `imageio_ffmpeg` со всеми данными/бинарниками;
- явно включает ключевые pywin32/COM-модули;
- запускает `--self-test` уже на упакованном EXE;
- пишет `[OK]` только после успешного packaged runtime test.

## Почему используется папка, а не один огромный EXE

Эта программа зависит от Windows COM/SAPI, `pywin32` и крупного FFmpeg-бинарника. Для такого приложения ONEDIR надёжнее one-file:

- не приходится распаковывать FFmpeg при каждом запуске;
- проще диагностировать отсутствующую DLL;
- меньше риск проблем антивируса с огромным самораспаковывающимся EXE;
- runtime-файлы остаются стабильными между запусками;
- настройки и логи по-прежнему создаются рядом с главным EXE.

Пользователь всё равно запускает один файл:

```text
Text-to-MP3-Windows.exe
```

## FFmpeg уже включён

Программа умеет брать FFmpeg из `imageio-ffmpeg`. Сборщик добавляет весь пакет `imageio_ffmpeg` в дистрибутив и до завершения сборки реально запускает его `ffmpeg -version`.

Отдельно скачивать FFmpeg, добавлять его в PATH или вручную копировать `ffmpeg.exe` не требуется.

## Windows SAPI и голоса

Программа использует стандартную Windows Speech API. Packaging self-test через `SAPI.SpVoice` проверяет, что COM/SAPI доступен и в системе есть хотя бы один голос.

SAPI является компонентом Windows. Набор конкретных голосов зависит от установленных языковых компонентов Windows; программа работает с доступными системными голосами. Сборщик не подменяет системные лицензированные голоса собственными файлами.

## Packaged self-test

Для сборки используется PyInstaller runtime hook `build_support/package_runtime.py`. В обычном запуске он ничего не меняет. При запуске:

```text
Text-to-MP3-Windows.exe --self-test
```

он до открытия GUI проверяет:

- загрузку `pythoncom` и `win32com.client`;
- создание `SAPI.SpVoice`;
- наличие хотя бы одного SAPI-голоса;
- наличие встроенного FFmpeg;
- успешный `ffmpeg -version`.

Поэтому простой факт создания EXE не считается достаточной проверкой.

## Повторная сборка

Просто ещё раз запустите `build_exe.bat`. Старый `dist/` удаляется автоматически. `.build-venv` можно оставить для ускорения следующих сборок; если удалить, BAT восстановит его.

## CI / Codex

```bat
build_exe.bat --ci
```

В режиме `--ci` BAT не ставит `pause` и возвращает корректный exit code. GitHub Actions выполняет тяжёлую packaging-проверку только на `[package]`-коммитах или при ручном `workflow_dispatch`, чтобы обычная документация не порождала лишние EXE-сборки.

## Если сборка упала

Смотрите первое сообщение `[ERROR]`/traceback выше итоговой строки. Наиболее вероятные причины:

- Python 3.13 отсутствует, а `winget` недоступен;
- PyPI блокируется proxy/антивирусом;
- Windows SAPI повреждён или в системе нет ни одного SAPI-голоса;
- build-папка недоступна для записи;
- антивирус блокирует новый unsigned EXE или FFmpeg.

BAT не скрывает ошибку и не сообщает об успехе, пока packaged self-test не завершится с кодом 0.

## Что можно удалить

После сборки можно удалить:

```text
build/
.build-venv/
Text-to-MP3-Windows.spec
```

Для запуска оставьте целиком:

```text
dist\Text-to-MP3-Windows\
```
